          WHY MONGODB + CLICKHOUSE? (Quick Answer)
════════════════════════════════════════════════════════════════════════

MONGODB (Users & Permissions):
  ✅ FAST writes (user signup, permission changes)
  ✅ Flexible schema (permissions can evolve)
  ✅ Already proven in your pilot
  ✅ Perfect for authentication
  ✅ 100-1000 users → MongoDB is perfect

CLICKHOUSE (Business Data):
  ✅ 100x FASTER for analytics
  ✅ Handles 50-60 crore rows
  ✅ Sub-second queries
  ✅ Perfect for aggregations

════════════════════════════════════════════════════════════════════════
                    COMPLETE USER FLOW
════════════════════════════════════════════════════════════════════════

STEP 1: USER SIGNUP
────────────────────────────────────────────────────────────────────────
Admin creates user → Selects checkboxes → Saves to MongoDB

MongoDB Document:
{
  "email": "user@company.com",
  "access_level": {
    "businesses": ["Food"],
    "channels": ["Convenience", "Direct"],
    "brands": ["Heinz", "Coca Cola"],
    "data_types": ["revenue", "profit"]  // NO costs
  }
}

════════════════════════════════════════════════════════════════════════

STEP 2: USER LOGIN
────────────────────────────────────────────────────────────────────────
User enters email/password → Backend verifies → Creates JWT token

JWT Token contains:
{
  "user_id": "usr_123",
  "access_level": {
    "businesses": ["Food"],
    "data_types": ["revenue", "profit"]
  }
}

Frontend stores token → All future requests include token

════════════════════════════════════════════════════════════════════════

STEP 3: DASHBOARD (RBAC Applied)
────────────────────────────────────────────────────────────────────────
User opens dashboard → Frontend sends request with JWT token

Backend:
1. Decode JWT → Get permissions
2. Build ClickHouse query WITH RBAC:

   SELECT date, business, channel, gsales, fgp
   FROM sales_analytics
   WHERE business IN ('Food')            ← RBAC Filter
   AND channel IN ('Convenience', 'Direct')  ← RBAC Filter
   AND brand IN ('Heinz', 'Coca Cola')      ← RBAC Filter

3. Execute on ClickHouse (Mac Studio)
4. Return ONLY user's authorized data

User sees:
  ✅ Food business data
  ✅ Revenue & profit (in data_types)
  ❌ Beauty business (not in access)
  ❌ Costs (not in data_types)

════════════════════════════════════════════════════════════════════════

STEP 4: AI CHATBOT (RBAC Applied)
────────────────────────────────────────────────────────────────────────
User asks: "What were my sales in January?"

Backend:
1. Decode JWT → Get permissions
2. Send to LLM WITH user context:

   "User can only see: businesses=['Food'], 
    channels=['Convenience', 'Direct']"

3. LLM generates SQL with RBAC:

   SELECT sum(gsales) FROM sales_analytics
   WHERE year=2025 AND month=1
   AND business IN ('Food')            ← RBAC Filter
   AND channel IN ('Convenience', 'Direct')  ← RBAC Filter

4. Backend validates query (safety check)
5. Execute on ClickHouse
6. LLM generates friendly response

User gets:
  "Your sales in January were €1.2M for the Food business..."

════════════════════════════════════════════════════════════════════════

STEP 5: USER TRIES UNAUTHORIZED ACCESS
────────────────────────────────────────────────────────────────────────
User asks: "Show me Beauty business sales"

Backend:
1. LLM generates: WHERE business = 'Beauty'
2. Backend checks: 'Beauty' in user permissions?
3. NO → Return error

User gets:
  "You don't have access to Beauty business data. 
   Please contact your administrator."

════════════════════════════════════════════════════════════════════════
                  RBAC LAYERS (Defense in Depth)
════════════════════════════════════════════════════════════════════════

Layer 1: JWT Token
  ✓ Must be logged in
  ✓ Token contains permissions

Layer 2: MongoDB Permissions
  ✓ Easy to update
  ✓ Flexible schema

Layer 3: ClickHouse Query Filters
  ✓ WHERE clause enforces access
  ✓ Column selection by data_types

Layer 4: LLM Context
  ✓ AI knows user's limits
  ✓ Generates safe queries

Layer 5: Backend Validation
  ✓ Final safety check
  ✓ Blocks unauthorized queries

════════════════════════════════════════════════════════════════════════
               WHY NOT PURE CLICKHOUSE?
════════════════════════════════════════════════════════════════════════

If we put users in ClickHouse:
  ❌ ClickHouse NOT designed for transactional writes
  ❌ Permission changes would be SLOW
  ❌ No built-in authentication
  ❌ Complex user management
  ❌ Still need MongoDB for app state anyway

MongoDB handles:
  • User authentication
  • Sessions & tokens
  • Permissions (easy updates)
  • Audit logs
  • Kanban, Action Items, etc.

ClickHouse handles:
  • 50-60 crore rows of business data
  • Fast analytics (< 500ms)
  • Aggregations

Each database does what it's best at! ✅
